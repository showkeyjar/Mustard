弱点 1：低意图查询空转 "none"（5 条，31.25%）

失败列表：d106 "嗯"、d107 "帮我看看"、d108 "不是那个"、d109 "太慢了"、d110 "分析"

根因：has_low_intent_signal() 对这 5 条全部返回 True。 policy.py 第 346-353 行的 low-intent gate 直接返回 Action.ANSWER + tool_call=None， 导致路由结果为 "none"。

触发机制：

  • Rule 1：len(text) ≤ 4 且无强信号 → "嗯"、"分析"、"不是那个"、"太慢了"、"帮我看看" 全部 ≤ 4 字
  • Rule 3：_LOW_INTENT_PATTERNS 中 ^.{0,4}$ 和 ^(帮我)?看看$ 匹配
  • 这些查询被判定为"无可操作意图"，直接拒绝而非路由

修复 1A：低意图 gate 改为默认路由 search（影响 5 条）

高优先 低风险 改动量 ~5 行

文件：carm/policy.py 第 344-353 行

思路：将 low-intent gate 从 "拒绝" 改为 "路由到 search"。哲学变更：当意图太模糊时，默认搜索比拒绝更合理——用户说了"嗯"或"分析"，大概率是想查什么。

# 修改前（第 344-353 行）：
if has_low_intent_signal(user_input):
    return ActionDecision(
        action=Action.ANSWER,
        score=0.9,
        reason="Low/no-intent query — no tool can meaningfully handle this.",
        tool_call=None,
        feature_snapshot=features,
    )

# 修改后：
if has_low_intent_signal(user_input):
    # Vague queries default to search — it's more helpful to
    # attempt a search than to reject the user.
    chosen_intent = IntentCategory.SEARCH
    chosen_tool = "search"
    chosen_reason = "Low-intent query — defaulting to search as fallback."
    hard_rule_hit = True
    action = Action.CALL_TOOL

预期效果：d106-d110 全部修复，准确率 92.20% → 94.63%

风险评估与回归防御

主要风险点

修复风险防御措施
修复 1A（低意图→search） "嗯" 等极短查询路由到 search 可能产生无意义搜索 在 search 工具内添加最短查询长度检查，或返回 "请补充更多信息" 提示
修复 2A（"还是" 信号） "还是算了吧" 等口语可能误触发 search 添加排除词："算了"、"别"、"不" — 当这些词与 "还是" 共现时不触发
修复 3A（compare 守卫例外） "比较两个方案并总结" 可能同时触发 compare 和 synthesis，需确认走合成而非搜索 修复后用 d066/d072 验证，并跑全部 205 条确认无回归

回归测试计划

  1. 每完成一个修复，立即跑 205 条 diverse_eval 验证 before/after
  2. 同时跑原有 63 条训练集 + 30 条留出集确认无回归
  3. 全部修复完成后，跑 python -m pytest tests/ -v 确认单元测试全通过
  4. 如新增 "还是" 信号可能影响 "比较类" 查询，额外检查 d049/d099/d186 等比较类 prompt

中长期改进方向

1. 从规则到混合路由（Phase 2）

当前 CARM 是纯启发式规则。16 条失败中有 3 条（d053/d159/d160）是因为无信号匹配， 落入语义编码器后选错。可在规则层和语义层之间增加一个轻量分类器（如 logistic regression）， 用信号特征作为输入，在语义编码器之前做一层拦截。

2. 真实流量 A/B 测试（Phase 3）

205 条评测集仍是开发者标注的，存在标注偏差。下一步应接入真实用户流量， 以 "用户是否在路由后重新手动选择工具" 作为隐式反馈信号，计算路由准确率。

3. 多轮对话上下文路由（Phase 3）

d106 "嗯"、d108 "不是那个" 这类低意图查询在多轮对话中其实有上下文含义。 未来应在路由器中引入会话记忆，用前序轮次的意图推断当前轮次的隐含意图。

4. 评测集扩展与独立标注（Phase 2）

当前 205 条由 CARM 开发者标注 "正确路由"，存在确认偏差。 应由不了解 CARM 设计的人独立标注 expected_tool，并扩展到 500+ 条覆盖更多边缘场景。

诚实说明： 以上修复方案基于 205 条评测集的 16 条失败分析。修复后 100% 准确率仅针对此评测集， 不代表真实用户场景下的表现。"还是" 信号添加等修改可能引入新的误判， 需要回归测试验证。此外，CARM 与 LLM 零样本的对比使用 gemma3:12b（12B 参数）， 非 GPT-4 级别模型，实际差距可能更大。中长期改进方向（混合路由、A/B 测试、独立标注） 比短期修复更能提升 CARM 的可信度。
