LLM 失败模式分析

gemma3:12b 的 14 条失败全部是误选 bigmodel_proxy——本应先搜索收集证据的查询， LLM 选择了直接合成。这说明 LLM 倾向于"看到冲突/比较/计划就合成"， 而 CARM 的路由逻辑要求这些场景先搜索后合成。

为什么 CARM 启发式路由优于 LLM 零样本

1. 领域特定规则：CARM 知道"冲突查询必须先搜证据再合成"， "比较查询先搜索信息再分析"。这些是 CARM 工作流的特定约定， 通用 LLM 在零样本下无法感知。

2. 延迟优势：CARM 路由是纯规则匹配，响应时间 <1ms。 LLM 单次推理 2-5s，批量 93 条耗时约 3 分钟。

3. 成本优势：CARM 零 API 调用。LLM 需要持续推理成本。

诚实说明： 本对比使用 gemma3:12b（12B 参数），非 GPT-4。GPT-4 在类似任务上通常表现更好， 实际差距可能缩小。此外，评测集由 CARM 开发者定义"正确路由"， 规则本身偏向 CARM 的设计哲学（先搜证后合成），对 LLM 存在结构性不利。 要做更公平的对比，建议：(1) 用 GPT-4o 或 Claude 3.5 重跑； (2) 由不了解 CARM 的人独立标注 expected_tool；(3) 测试 LLM 在更好的 system prompt 下的表现。
